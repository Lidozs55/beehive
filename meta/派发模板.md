# 章节写作子代理派发模板

> 本模板由主代理使用。方括号内为派发前必须填写或删除的内容；不得把互相冲突的候选信息同时交给子代理。

## 一、标准派发块

---
你是《蜂巢》章节写作子代理，负责创作第【{PID}】《{标题}》。

【交付】
- 正文写入：`正文/{文件名}`
- 目标篇幅：【{目标字数或范围}】；篇幅服务于场景完成度，明显偏离时在回执说明原因。
- 只修改上述正文文件。不得修改 `state/`、`bible/`、`characters/`、`chapters/`、`arcs/`、`meta/`、`audits/` 和工具脚本；不得执行 git 写操作。

【本章任务】
- 一句话方向：【{谁想做什么，受什么阻碍，结束时什么改变}】
- 必须完成：【{本章节点/场景卡要点，逐条列出}】
- 可以调整：【{场景次序、次要动作、局部对话等可自由处理项}】
- 不得提前兑现：【{后续章内容、未揭示设定、未到期伏笔}】

【叙事边界】
- 视角与距离：【{视点人物、近距/有限/其他约定}】
- 时间与地点：【{从 timeline-log 逐字引用或给出明确锚点}】
- 出场人物及当前状态：【{只列本章相关人物}】
- 当前知情边界：【{谁知道什么、谁不知道什么、读者可知到哪里}】
- 逐字口径：【{任务牌/面板/章程/原话/数字；无则写“无”}】
- 连续性红线：【{无来源证据、能力边界、物件去向、时间约束等}】

【按序阅读】
1. `.agents/skills/novel-skill/SKILL.md`
2. `.agents/skills/novel-skill/references/05-场景与章节.md`
3. `.agents/skills/novel-skill/references/07-文风与语言修订.md`
4. `style-guide.md`
5. `state/handoff.md`
6. `state/character-state.md`【{出场人物行/区间}】
7. `state/established-facts.md`【{本章及邻近事实区间；禁止读取的未来区间写明}】
8. 运行 `python tools/slice_summaries.py {上一章PID} {本章PID}`，只读取输出的两章节点；禁止全量读取 `state/summaries.md`
9. `state/timeline-log.md`【{本章行}】
10. `正文/{上一章文件名}`（全文；若不是直接承接，说明本章开头的时间跳转）
11. 【P001-P018填明细场景卡；P019起写“以 handoff 第X-X行为本章简报”，并附对应事件骨架/故事弧来源；不要假设后续章另有逐章细卡】
12. 【{证据链、人物原话、机制或物件的来源正文/设定文件；没有则删除本项}】
13. 【按需模块：对话密集加 `06-对话工艺.md`；悬念/反转加 `04-情节与悬念.md`；世界规则或技术机制加 `08-世界观构建.md`；多世界/试炼机制加 `12-多世界与试炼结构.md`。未指定的不要自行扩读。】

【写作要求】
1. 动笔前先用一句内部工作句确认本章目标，但不要把工作句写进正文。
2. 让人物选择和可见后果推动章节；不得用旁白替人物补动机，也不得把摘要或台账措辞直接冒充正文原话。
3. 保持与上一章的时间、空间、物件和情绪连续。若有跳转，在正文中给出足够清楚的过渡。
4. 优先完成故事和人物，再按 `style-guide.md` 修订叙事距离、信息投放、句段节奏和套话。不要为词频配额批量替换词语。
5. 发现派发材料互相冲突、必要来源缺失或计划无法在既有规则内成立时，停止扩写冲突部分，并在回执报告；不要自行发明新权限、新证据或规则例外。

【提交前检查】
- 本章要求是否实际写入正文，而非只在回执声称完成。
- 关键结果是否有已铺垫的证据、能力、资源和因果链。
- 人物是否只使用其当前可知信息。
- 逐字口径、数字、时间、地点、人物状态和物件去向是否一致。
- 开头是否清楚进入本章，结尾是否形成有效变化或余波；不强制使用特定钩子或收尾类型。
- 是否有抽象总结可改为更具体的动作、原话、物件或后果。

【最终回执】
1. 正文文件：路径、实际字数、是否完整写入。
2. 要点覆盖：逐条写“已完成/部分完成/未完成 + 正文中的场景或段落定位”，不要大段引用正文。
3. 连续性核对：时间地点、知情边界、逐字口径、关键物件和能力来源；只展开有风险或发生变化的项。
4. 状态变更提案：建议追加的已写事实、人物状态、时间线、摘要、钩子开合；给出简洁措辞，不直接修改状态文件。
5. 偏离与问题：说明对派发要求的有意偏离、材料冲突或待主代理裁决事项；没有写“无”。
---

## 二、派发前参数生成

运行：

```bash
python tools/gather_dispatch.py P0XX
```

脚本输出用于定位计划条目、场景卡、事实区间、摘要、时间线、钩子和上一章文件。主代理必须人工核对后再填入标准派发块；脚本输出不是完整提示词，也不证明信息无冲突。

## 三、主代理派发前检查

1. 目标正文路径不存在，或明确允许覆盖当前草稿。
2. `state/handoff.md` 的下一章与派发 PID、标题、时间地点一致。
3. 本章场景卡、故事弧或 handoff 章节简报足以执行，并与 `summaries`、`timeline-log`、`established-facts` 没有互相冲突；不为已有完整简报重复建卡。
4. 已列出出场人物状态、知情边界、逐字口径、本章不得提前兑现的内容，以及关键证据/设备/档案的取得权限与受理方。缺少权限或证据来源属于派发阻断项，先由主代理补足或裁决。
5. 只派发与本章有关的事实区间和来源章节；区间止于本章最后一条事实，不得包含后续未写章。重要原话与数字应给出处，不让子代理凭摘要猜。
6. 对话、悬念、世界观或试炼模块只按实际风险添加，不一次加载全部 skill 参考。
7. 若本章是战斗、规则破解、重大揭示、伏笔回收、关系转折或卷/弧收尾，主代理应在回收后阅读全文，不只依赖回执。

## 四、主代理回收流程

1. 确认只有指定正文文件发生变化，并读取正文全文。
2. 先复核阻断问题：事实冲突、知情越界、无来源解法、人物重大失真、时间空间或物件断裂。
3. 再复核章节目标、人物选择、信息节奏和项目风格；词频与对话占比只作为定位异常的信号。
4. 根据正文实际发生的变化更新状态文件。不得把子代理回执或原计划直接登记为已写事实。
5. 运行 `python tools/validate_workspace.py`；涉及人口、资源或结构镜像时运行相应专项工具。

## 五、模板设计说明

- `05-场景与章节.md` 和 `07-文风与语言修订.md` 是章节写作的常规参考；其他模块按风险添加。
- 不要求固定“六步流程”、八项评分表、词频配额、对话比例或每章强钩。这些规则容易让子代理为通过表格牺牲场景自然度。
- 回执保留“要点覆盖、连续性、状态提案、问题”四类可核验信息。主代理据此定位风险，但必须以正文为准。
- 主代理负责状态落盘和跨文件裁决，子代理负责单章正文。这个权限边界应保持稳定。
