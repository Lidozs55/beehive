# 小说创作

## 定位

本文件只负责三件事：判断任务、选择工作深度、路由参考模块。具体工艺由 `references/` 中的专题文件负责，不要一次加载全部模块，也不要把全部检查表展示给用户。

适用任务：原创小说、中文网文、类型融合、科幻、悬疑、冒险、多世界或试炼结构、同人、续写、改写、诊断、世界观或大纲设计。题材标签只用于选择工具，不用于反向限制作品；短篇可轻量执行，长篇按风险逐步建立外部状态。

正文默认直接在对话中交付；用户要求文件或项目已有正文目录时再落盘。格式服从用户或项目约定，不因“小说”自动创建 Markdown、HTML 或整套目录。

## 决策优先级

发生冲突时按以下顺序裁决：

1. 用户明确要求与项目既有约定。
2. 已发布或已确认的正文事实、人物行为和叙述声音。
3. 题材承诺、目标读者与当前场景需要。
4. 因果、视角信息边界、世界规则等连续性约束。
5. 本 skill 的默认方法与数值参考。

除安全、事实连续性和用户硬约束外，本 skill 中的比例、次数、章数、字数、阈值都默认是**诊断信号**，不是自动判废线。偏离时先问“是否产生了可感知的问题”，再决定是否修改。

## 创作原则

- **约束产生戏剧**：能力有边界，选择有机会成本，规则对各方一致。
- **人物通过选择成立**：档案用于预测行为，不用于替代正文；人物可改变，但变化必须被事件推动并可回溯。
- **情节靠因果前进**：场景应改变目标、处境、关系、认知或读者期待，安静场景也可通过积累意义发挥作用。
- **信息按体验投放**：设定优先通过行动、后果、误读与发现进入正文；必要的简洁讲述并非缺陷。
- **长篇依赖可检索记忆**：状态系统随项目复杂度增长，不为尚不存在的问题预建文件。
- **风格服务作品**：去除无意的套话与重复，不以禁词表消灭作者声音，不把“像 AI”当作脱离语境的定罪标签。

## 先判断任务

收到请求后，在内部确认：

- 任务：构思 / 立项 / 大纲 / 写作 / 续写 / 改写 / 诊断 / 设定。
- 规模：片段、单章、短中篇、长篇或持续连载。
- 类型：题材、受众、平台倾向、叙述视角与基调。
- 依据：是否有旧稿、大纲、人物档案、风格样本或状态文件。
- 交付：用户要正文、方案、批注、修改稿，还是项目文件更新。

能从上下文稳妥推断的直接推断，并简短说明关键假设。只有缺失信息会导致完全不同的作品方向、同人对象无法确认、已有材料不完整或设定存在不可兼容冲突时才提问；一次集中问最少的关键问题。

## 工作深度

### 快速模式

用于片段、单章、灵感试写、局部润色和短诊断。

1. 读取用户提供的全部相关文本。
2. 明确本次场景目标、视点、变化与情绪落点。
3. 直接创作或修改。
4. 只检查本次最相关的 3-5 项，不输出冗长自检表。

通常加载：`05-场景与章节.md`；按需叠加 `06-对话工艺.md`、`07-文风与语言修订.md`。

### 标准模式

用于短中篇、章节组、大纲、已有稿续写或重要改写。

1. 提取作品承诺与不可动项。
2. 建立足够而非完整的角色、因果和信息边界。
3. 先写最小可用方案或近程路线，再创作。
4. 完成针对性审计；只汇报影响交付的问题。

### 长篇模式

用于预计跨多章持续协作、长篇连载或复杂群像。

1. 读取项目现有地图与状态，不假设固定目录。
2. 建立最小状态集：当前进度、人物状态、开放线索、下一步。
3. 每次只规划足以稳定当前弧线的范围，保留局部即兴空间。
4. 写后更新发生变化的状态；无变化的文件不做形式化刷新。
5. 在弧线或卷级边界做宏观复盘，而非每章执行全套量化审计。

状态系统详见 `09-长篇状态管理.md`。

## 章节循环

章节循环是默认流程，可按任务裁剪，不是六道强制关卡：

1. **校准**：读上一章关键段、当前状态、本章相关人物与未决承诺。
2. **定向**：用一句话写明“谁想做什么，受什么阻碍，本章结束后什么改变”。
3. **起草**：保持视点和因果连续，让人物选择推动场景。
4. **修订**：先结构与人物，再信息与节奏，最后句子；不要边写每句边跑完整清单。
5. **同步**：只记录本章造成的事实、状态、线索和计划变化。

用户只要正文时，不附带内部要点表、自检分数或状态日志，除非这些本身也是交付要求。

## 质量底线

以下属于高优先级问题：

- 关键结果依赖未铺垫的能力、信息、道具或援助。
- 视点人物知道其无法获得的信息，且文本未建立解释。
- 已确立的世界规则只为主角临时失效。
- 人物重大转变既无压力事件，也无渐进迹象。
- 悬念靠隐瞒叙述者本应提供的事实，而非公平的信息控制。
- 改稿破坏了前后依赖，却未做回归检查。
- 作品采用的科技、试炼或多世界机制无法说明其规则如何被发现、验证、利用或承受后果。

以下不是自动缺陷：慢章、无强钩结尾、长对话、全知视角、场景切换、直接讲述、人物打破旧原则、以谈判解决冲突。判断它们是否损害作品承诺、可读性或可信度。

## 旧稿与风格参考

续写或改写前，读取用户指定范围及必要的前后文。材料过长时可分批提取状态，但不要声称未读部分已经检查。

模仿参考作品时，提取可描述的高层特征：叙事距离、句法节奏、视点习惯、意象来源、对话密度、幽默或压迫机制。不要复制独特句子，也不要承诺精确复刻在世作者的个人风格；转化为项目自己的风格说明。

## 交付

- 创作任务优先交付作品本身，说明保持简短。
- 诊断任务先给最高影响问题及文本证据，再给修法；用户要求时直接改稿。
- 长篇协作说明更新了哪些状态，以及仍有哪些有意开放的问题。
- 不创建审计报告、计划总结或整套目录，除非用户明确需要持久化产物或项目已有约定要求。
